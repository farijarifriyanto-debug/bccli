# BCCLI v0.3 — Provider menu, MCP, subagent, skill/perintah, todo (desain)

Tanggal: 2026-09-27 · Status: menunggu review · Dibangun di atas v0.2 (`main`, 97d5e7c)

## Tujuan

v0.2 sengaja minimal. Pengguna yang mencobanya menilai BCCLI "belum terasa seperti
agent": provider hanya bisa ditambah lewat file, tidak ada MCP, subagent, skill,
atau todo list. v0.3 melengkapi semuanya **sebelum** dirilis, dengan prinsip:

> Pengguna tidak perlu memasang atau mengatur apa-apa sendiri. `npm i -g`,
> `bccli login`, lalu provider populer, MCP umum, subagent, dan skill tersedia
> lewat menu — tanpa menyunting file config.

Kriteria berhasil:
1. Pengguna baru bisa menambah provider, memilih model dari provider mana pun, dan
   memasang MCP dari katalog **hanya lewat menu** (`/provider`, `/model`, `/mcp`).
2. Agent bisa mendelegasikan pencarian ke `explore` dan pekerjaan ke `general`
   tanpa mengotori konteks utama.
3. Skill dan perintah yang sudah dimiliki untuk Claude Code (`.claude/skills`,
   `.claude/commands`, `.claude/agents`) langsung bisa dipakai.
4. Tugas multi-langkah menampilkan todo list; mode plan berakhir dengan persetujuan
   rencana yang langsung mengganti mode dan mulai bekerja.
5. Semua hal di atas tidak melemahkan model izin v0.2.

## Keputusan yang sudah disepakati

| Topik | Keputusan |
|---|---|
| Provider | Preset bawaan populer + custom; BotConnector Cloud default |
| Daftar model | `/model` menampilkan model dari **semua** provider yang punya key, dikelompokkan per provider |
| MCP | Katalog bawaan, pasang sekali klik lewat `/mcp`; tidak ada yang aktif otomatis |
| Klien MCP | SDK resmi `@modelcontextprotocol/sdk` (stdio + HTTP) |
| Subagent | `explore` + `general` bawaan + agent custom `agents/*.md` |
| Skill/perintah | Format standar Agent Skills (`SKILL.md`, `commands/*.md`); ikut membaca `.claude/` |
| Rilis | Sekali setelah semua selesai: `0.3.0-beta.1`, dist-tag `next`; `beta`/`latest` tidak disentuh |

## 1. Provider

Preset bawaan (ada di kode, tidak perlu ditulis ke config):

| Id | Nama tampilan | Base URL | Env key |
|---|---|---|---|
| `bc-cloud` | BotConnector Cloud | `https://api.botconnector.id/v1` | `BOTCONNECTOR_API_KEY` |
| `openrouter` | OpenRouter | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` |
| `openai` | OpenAI | `https://api.openai.com/v1` | `OPENAI_API_KEY` |
| `gemini` | Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `GEMINI_API_KEY` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` | `DEEPSEEK_API_KEY` |
| `groq` | Groq | `https://api.groq.com/openai/v1` | `GROQ_API_KEY` |
| `ollama-cloud` | Ollama Cloud | `https://ollama.com/v1` | `OLLAMA_API_KEY` |
| `ollama` | Ollama lokal | `http://127.0.0.1:11434/v1` | — |
| `lmstudio` | LM Studio lokal | `http://127.0.0.1:1234/v1` | — |

URL di tabel diverifikasi ulang di tahap rencana; yang tidak bisa diverifikasi tidak
dimasukkan.

`/provider` (menu):
1. Daftar preset + provider custom dengan status `✓` key tersedia / `○` belum.
2. Pilih → bila perlu key: input tersembunyi → cek `GET /v1/models` → simpan di
   `~/.bccli/credentials` (mode 600).
3. Langsung tampil daftar model provider itu; pilihan menjadi model aktif dan
   **default** (ditulis ke `~/.bccli/config.json`).
4. "Custom…": nama, base URL, key (opsional) → ditulis ke `providers` di config global.

CLI non-interaktif: `bccli provider list | add <id> | remove <id>`.

`/model`:
- Mengambil `/v1/models` dari **semua** provider yang punya key (dan provider lokal
  yang merespons), paralel, timeout 5 detik per provider; yang gagal ditandai
  "tidak bisa dihubungi" dan dilewati.
- Dikelompokkan per provider (header nama provider); model aktif ditandai.
- Ketik untuk menyaring (substring, tidak peka huruf besar).
- Pilihan disimpan sebagai default.
- Header dan status bar menampilkan `model · Nama Provider`.

Aturan kepercayaan v0.2 tetap: config project tidak bisa mengubah provider yang
sudah dikenal (termasuk preset) atau mengikat env key.

## 2. MCP

Katalog bawaan (`/mcp`), status `✓` terpasang / `○` belum / `✗` error. Isi awal
(nama paket/URL diverifikasi di tahap rencana; entri yang tidak terverifikasi
dibuang):

| Nama | Fungsi | Transport |
|---|---|---|
| playwright | kontrol browser | stdio (`npx`) |
| context7 | dokumentasi library | HTTP remote |
| fetch | ambil halaman web | stdio (`uvx`) |
| filesystem | akses folder di luar project | stdio (`npx`) |
| git | operasi git terstruktur | stdio (`uvx`) |
| github | issue/PR/repo | HTTP remote, butuh token |
| postgres | query database | stdio (`npx`), butuh URL DB |

Perilaku:
- Pasang dari katalog; isian yang dibutuhkan (token, URL) diminta lewat menu.
  Disimpan di `~/.bccli/mcp.json` dengan format `mcpServers` seperti Claude Code
  (`command`/`args`/`env` untuk stdio, `url`/`headers` untuk HTTP).
- CLI: `bccli mcp list | add <nama-katalog> | add --url <url> <nama> | remove <nama>`.
- Saat start, server terpasang dijalankan di latar belakang; alatnya tersedia sebagai
  `mcp__<server>__<alat>`. Server yang gagal tidak menghalangi start; `/mcp`
  menampilkan `✗` + pesan error.
- **Izin:** semua alat MCP berjenis izin `mcp` dan selalu ditanya; `[a]` berlaku per
  alat (`mcp(<server>__<alat>)`) untuk sesi; `allowAll` melewati; `plan` menolak.
- **MCP dari project** (`.bccli/mcp.json`) tidak dijalankan otomatis: pertama kali
  ditanya "Repo ini ingin menjalankan server MCP X. Izinkan?"; jawaban diingat per
  folder di `~/.bccli/trusted-mcp.json`.
- Server ditutup rapi saat BCCLI keluar (termasuk Ctrl+C).

## 3. Subagent

Alat `task(agent, description, prompt)` untuk agent utama. Menjalankan `Agent` baru
dengan riwayat kosong, system prompt dari definisi agent, dan hanya alat yang
diizinkan; yang dikembalikan ke agent utama hanya jawaban akhirnya.

| Agent | Alat | Batas langkah |
|---|---|---|
| `explore` (bawaan) | `read`, `grep`, `glob` | 30 |
| `general` (bawaan) | semua kecuali `task` | 50 |
| custom | sesuai `tools` di file | 50 |

Agent custom dibaca dari `~/.bccli/agents/*.md`, `.bccli/agents/*.md`,
`~/.claude/agents/*.md`, `.claude/agents/*.md` (project menang bila nama sama).
Frontmatter: `name`, `description`, `tools` (daftar nama alat, opsional = semua kecuali
`task`), `model` (`provider/model`, opsional = ikut model utama). Isi file = system
prompt agent.

Aturan:
- Subagent tidak punya alat `task` (tidak ada rantai).
- Izin sama dengan agent utama (mode dan aturan sesi dipakai bersama); prompt izin
  diberi label nama agent, mis. `[general] Izinkan edit a.ts?`.
- Beberapa `task` dalam satu langkah: `explore` paralel, lainnya berurutan.
- Esc membatalkan subagent yang berjalan; token subagent ikut dihitung di `/cost`.
- Model custom hanya boleh memakai provider tepercaya (config global/preset).
- UI: blok `⎿ Task [agent]  deskripsi` dengan alat-alat subagent diindentasi di
  bawahnya, ditutup `✓ selesai · N langkah · Xk token` atau `✗ …`.

## 4. Skill dan perintah custom

Skill: folder berisi `SKILL.md` (frontmatter `name`, `description`) dari
`~/.bccli/skills/`, `.bccli/skills/`, `~/.claude/skills/`, `.claude/skills/`
(project menang bila nama sama).
- Nama + deskripsi (maks 50 skill, deskripsi ≤ 200 karakter) masuk system prompt.
- Alat `skill(name)` mengembalikan isi `SKILL.md` + path foldernya; agent
  memanggilnya bila deskripsi cocok. File lain di folder dibaca dengan `read`.
- Pengguna bisa memanggil langsung: `/nama-skill argumen`.

Perintah: `commands/*.md` dari `~/.bccli/commands/`, `.bccli/commands/`,
`~/.claude/commands/`, `.claude/commands/`.
- `/nama teks` mengirim isi file sebagai pesan user, `$ARGUMENTS` diganti `teks`.
- Frontmatter opsional: `description`, `argument-hint`.
- Perintah bawaan selalu menang bila nama bentrok.

Saran `/` dan `/help` menampilkan tiga kelompok: bawaan, perintah custom, skill.
Skill dan perintah hanya teks instruksi; tidak menambah izin.

## 5. Todo list dan mode plan

Todo:
- Alat `todo_write(todos: {content, status: pending|in_progress|completed}[])`,
  mengganti seluruh daftar tiap panggilan; tidak butuh izin.
- System prompt: pakai untuk tugas ≥ 3 langkah; tepat satu `in_progress`.
- UI: checklist menempel di atas kotak input selama ada item belum selesai
  (`☑` selesai, `◼` sedang, `☐` belum).

Mode plan:
- Alat `exit_plan(plan)` hanya tersedia di mode plan.
- UI menampilkan rencana (markdown) dan bertanya:
  `[a] ya, edit otomatis · [y] ya, tanya tiap langkah · [n] belum, perbaiki dulu`.
- `a` → mode `acceptEdits`, `y` → `default`; agent langsung lanjut mengerjakan.
  `n` → tetap plan; hasil alat memberi tahu agent untuk memperbaiki rencana.
- Mode `-p`: `exit_plan` ditolak kecuali `--allow-all` (tidak ada yang bisa menyetujui).

## Arsitektur (tambahan terhadap v0.2)

```
src/
  providers.ts      preset provider + tulis config global (provider/model default)
  models.ts         kumpulkan /v1/models dari semua provider (paralel, timeout)
  mcp/
    catalog.ts      katalog bawaan
    config.ts       baca/tulis mcp.json global + project, trust per folder
    manager.ts      start/stop klien SDK, daftar alat → Tool
  agents.ts         definisi explore/general + loader agents/*.md
  extensions.ts     loader skill + commands (frontmatter kecil, tanpa dependensi)
  tools/task.ts     alat task (menjalankan Agent anak)
  tools/skill.ts    alat skill
  tools/todo.ts     alat todo_write
  tools/plan.ts     alat exit_plan
  ui/ProviderMenu.tsx, ui/McpMenu.tsx, ui/ModelPicker.tsx (dengan grup + filter),
  ui/TodoList.tsx, ui/PlanApproval.tsx
```

- Alat tetap satu antarmuka `Tool`; alat MCP dibungkus menjadi `Tool` dengan
  `kind: 'mcp'`. Daftar alat agent menjadi dinamis (bawaan + MCP), dihitung ulang
  saat server MCP berubah.
- `Agent` mendapat opsi `label` (nama agent untuk prompt izin) dan event bersarang
  `subagent` untuk UI.
- Dependensi baru: `@modelcontextprotocol/sdk` saja. Frontmatter diparse dengan
  parser kecil sendiri (hanya `key: value` dan daftar `[a, b]`).
