# BCCLI v0.4 — Perintah sesi, info, izin, dan kode (desain)

Tanggal: 2026-09-27 · Status: menunggu review · Dibangun di atas `0.3.0-beta.3` (`main`, daab99a)

## Tujuan

Pengguna yang mencoba v0.3 menemukan menu masih kurang dibanding Claude Code / Codex:
belum bisa membuat sesi baru, melanjutkan sesi, atau melihat status dari dalam
BCCLI. v0.4 menambahkan 15 perintah `/` sehingga pengguna tidak perlu keluar dari
BCCLI untuk urusan sehari-hari.

Kriteria berhasil:
1. Semua perintah di bawah tersedia di saran `/` dan `/help`, dengan pilihan ↑↓/Enter
   seperti perintah lain.
2. `/undo` mengembalikan file persis seperti sebelum giliran agent terakhir.
3. Tidak ada perintah yang melemahkan model izin v0.3.

## Perintah

### Sesi
| Perintah | Perilaku |
|---|---|
| `/new` | Buat sesi baru (file jsonl baru), kosongkan percakapan, todo, dan checkpoint undo. Sesi lama tetap tersimpan. |
| `/resume` | Picker sesi di folder ini (tanggal, preview pesan pertama, jumlah pesan; ↑↓, ketik untuk menyaring, esc batal). Setelah dipilih: `runtime.resume(session)`, tampilkan 3 pesan user/asisten terakhir sebagai notice. |
| `/session` | Waktu mulai, jumlah pesan, token (masuk/keluar), model, path file sesi. |
| `/export [path]` | Tulis percakapan (pesan user dan asisten; alat diringkas `⎿ Nama target`) ke markdown. Default `./bccli-YYYY-MM-DD-HHMM.md`. Menulis file di folder project tanpa izin tambahan karena diminta langsung oleh user. |

### Info
| Perintah | Perilaku |
|---|---|
| `/status` | Versi, model + provider, mode izin, folder, jumlah MCP aktif/error, token sesi, perkiraan konteks terpakai (`lastInputTokens` / 128k). |
| `/agents` | Subagent bawaan + custom: nama, deskripsi, alat (atau "semua"), model (atau "ikut utama"). |
| `/skills` | Skill (nama, deskripsi, folder) dan perintah custom (nama, deskripsi). |
| `/doctor` | Cek: versi Node (≥ 22), key tiap provider (✓/○), koneksi `/v1/models` provider aktif (ok/gagal + pesan), status tiap server MCP, ketersediaan `rg`, `git`, `npx`, `uvx` di PATH. |

### Izin dan instruksi
| Perintah | Perilaku |
|---|---|
| `/permissions` | Daftar aturan izin aktif dengan asalnya (`config` atau `sesi`). Pilih aturan sesi + Enter → dicabut. Aturan dari config hanya ditampilkan (dicabut dengan mengedit `~/.bccli/config.json`). |
| `/memory` | Tanpa argumen: daftar file instruksi yang terbaca (path + jumlah baris). `/memory <teks>`: tambah `- <teks>` ke `AGENTS.md` di folder project. `/memory global <teks>`: tambah ke `~/.bccli/BCCLI.md`. System prompt agent dibangun ulang setelahnya. |
| `/init` | Kirim prompt bawaan ke agent: pelajari project lalu buat/perbarui `AGENTS.md` (build/test/lint commands, struktur, konvensi). Penulisan file lewat alat `write`/`edit` biasa (tetap butuh izin). |
| `/login` | Minta API key provider aktif (input tersembunyi), verifikasi, simpan — alur sama dengan `/provider`. |
| `/logout` | Hapus key tersimpan provider aktif dari `~/.bccli/credentials`; beri tahu bila provider masih mendapat key dari env var. |

### Kode
| Perintah | Perilaku |
|---|---|
| `/diff` | `git diff --stat` lalu `git diff` (berwarna, maks 400 baris, sisanya "… N baris lagi"). Di luar repo git: pesan jelas. |
| `/undo` | Membatalkan **semua** perubahan file oleh alat `write`/`edit` pada giliran agent terakhir; bisa diulang mundur per giliran. File yang dibuat baru dihapus; file yang diubah dikembalikan ke isi aslinya. Perubahan lewat `bash` tidak bisa di-undo — disebut di pesan hasil. |
| `/copy` | Salin jawaban asisten terakhir ke clipboard dengan OSC 52 (bekerja lewat SSH/Termius bila terminal mendukung) **dan** selalu simpan ke `~/.bccli/last-answer.md`, lalu beri tahu keduanya (terminal tidak memberi konfirmasi apakah OSC 52 berhasil). |

## Desain teknis

- **Checkpoint undo:** `CheckpointStore` di runtime. Agent menandai awal giliran
  (`beginTurn()`); alat `write`/`edit` memanggil `ctx.checkpoint?.(absPath)` sebelum
  menulis. Store menyimpan isi asli (atau "tidak ada") per file, sekali per file per
  giliran, di memori (maks 20 giliran; file > 2 MB tidak disimpan dan diberi tahu).
  `/undo` mengembalikan giliran terakhir yang punya perubahan. `/new` mengosongkan store.
- **Perintah UI:** semua ditambahkan ke `SLASH_COMMANDS` dan ditangani di `runSlash`;
  logika non-UI (status, doctor, export, memory, permissions list, diff) di modul kecil
  `src/commands/*.ts` yang mengembalikan teks/data sehingga bisa dites tanpa Ink.
- **Picker generik:** `/resume` dan `/permissions` memakai satu komponen `ListPicker`
  (judul, item `{ id, label, hint? }`, filter ketik, ↑↓ enter esc).
- **Permissions:** `Permissions` mendapat `list(): { rule: string; source: 'config' | 'session' }[]`.
- **Memory:** `Agent` mendapat `setSystemPrompt(text)`; runtime `rebuildSystemPrompt()`.
- **OSC 52:** tulis `\x1b]52;c;<base64>\x07` ke stdout (dalam tmux dibungkus
  `\x1bPtmux;…\x1b\\`).
